# Проверка ответов после интернет-поиска

С версии 1.16.1 маршрут проверки фактов можно выбрать отдельно от голосовых. Измените рабочий `.env` и перезапустите существующий экземпляр бота.

## Сервер без прямого доступа к Google

```env
RESEARCH_REVIEW_PROVIDER=openrouter
```

Проверка прочитанных материалов и готового ответа использует существующий текстовый клиент OpenRouter и его основную модель. Ключ берётся из `OPENROUTER_API_KEY`, а если его нет, из `AI_API_KEY`. Если заданы обе переменные, приоритет у `OPENROUTER_API_KEY`. Новый ключ не требуется.

Если `AI_BASE_URL` задан явно, укажите:

```env
AI_BASE_URL=https://openrouter.ai/api/v1
```

В этом режиме проверяющая модель получает весь доступный срок. Прямого обращения к Google из проверки нет, время для него не резервируется. Название модели `google/...` в OpenRouter означает модель за API OpenRouter, а не прямой запрос сервера бота к Google.

Поиск страниц остаётся отдельной функцией. Для существующего поиска через Tavily сохраните `SEARCH_PROVIDER=tavily` и свой `TAVILY_API_KEY`. Эта настройка не заменяет поисковый ключ и не переводит анализ видео или другие нативные функции в OpenRouter.

## Сохранить основной API и рабочий Google-резерв

```env
RESEARCH_REVIEW_PROVIDER=auto
```

Это значение по умолчанию. Если переменная отсутствует, действующий маршрут сохраняется. При наличии обоих провайдеров часть срока остаётся Google-резерву. Когда настроен только один провайдер, он получает весь доступный срок проверки.

Наличие Google-ключа само по себе не доказывает доступность Google с сервера. Если прямой Google заведомо не работает, выберите `openrouter` явно.

## Проверять напрямую через Google

```env
RESEARCH_REVIEW_PROVIDER=google
```

Используется только нативный Google-клиент с существующими Google-ключами. OpenRouter для проверки не вызывается. Эта настройка не меняет модель обычных ответов или голосовых.

## Что происходит при сбое

На полную финальную проверку отведено до 40 секунд. Если она не дала пригодного результата, бот может собрать короткий кандидат по имеющимся выводам и отдельно проверить его по исходным материалам. На эту единственную дополнительную проверку отведено до 25 секунд в общем пределе финального этапа 65 секунд. Нового поиска для неё нет.

Короткая версия публикуется только при успешной проверке. Она сохраняет ссылки и оговорки, а непрочитанные исходные страницы остаются явно обозначенным пробелом. Если обе проверки не дали пригодного результата, бот сообщает о причине отказа. Тайм-аут и недоступность сервиса больше не называются обнаруженной неточностью ответа.

Этот предел относится к финальной проверке после подготовки черновика. Поиск, чтение страниц и подготовка текста занимают дополнительное время. Доступность и скорость внешних API не гарантированы.

Короткая проверка является дополнительным модельным запросом только при отказе полной проверки. В режиме `auto` у проверки может быть основной и резервный провайдер. Прежний непроверенный черновик не публикуется, автоматических бесконечных попыток нет.

## Проверка после обновления

1. Сохраните резервную копию кода, `.env` и папки `data`.
2. Остановите текущий экземпляр, обновите код, сохраняя свой `.env` и `data`.
3. Выполните `npm ci --omit=dev`, запустите бот прежним способом.
4. Проверьте лог: `[RESEARCH] review_provider=openrouter`, `auto` или `google`.
5. Задайте вопрос, явно требующий интернет-поиска. Если есть исходные ссылки, приложите их. Проверьте, что ответ относится к вопросу, содержит подходящие ссылки и не скрывает пробелы.

Если режим не применился, проверьте `.env` именно работающей копии и окружение PM2/systemd: переменные процесса имеют приоритет над `.env`. Не запускайте второй процесс с тем же Telegram-токеном. При откате восстановите прежний код и настройки, сохраняя актуальную папку `data`.

Для голосовых по-прежнему используется отдельная настройка:

```env
VOICE_TRANSCRIPTION_PROVIDER=openrouter
```

Для молчаливого отключения голосовых её значение должно быть `off`. Подробности в [инструкции по голосовым](voice-setup.md).
