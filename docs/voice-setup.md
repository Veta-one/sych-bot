# Настройка голосовых сообщений

С версии 1.16.0 голосовые сообщения и аудиофайлы можно обрабатывать через Google, через OpenRouter или полностью игнорировать. Настройка находится в рабочем `.env`, рядом с `package.json`. После её изменения перезапустите текущий процесс бота.

## Сохранить прежнюю работу через Google

```env
VOICE_TRANSCRIPTION_PROVIDER=google
```

Это значение по умолчанию. Если переменной нет, обновление сохранит прежний маршрут через Google с ключами `GOOGLE_GEMINI_API_KEY`, `GOOGLE_GEMINI_API_KEY_2` и далее. Резервная модель и повторы этого режима сохраняются.

## Расшифровывать через OpenRouter

Если текст уже работает через OpenRouter, добавьте или замените одну строку:

```env
VOICE_TRANSCRIPTION_PROVIDER=openrouter
```

Используется тот же ключ, что для текста: `OPENROUTER_API_KEY`, а если его нет, `AI_API_KEY`. Если заданы обе переменные, приоритет у `OPENROUTER_API_KEY`. Нового ключа для аудио не нужно. При отсутствии `AI_BASE_URL` используется `https://openrouter.ai/api/v1`. Если адрес задан явно, он должен быть таким:

```env
AI_BASE_URL=https://openrouter.ai/api/v1
```

Аудио отправляется в модель `google/gemini-2.5-flash-lite` через OpenRouter. Для этого маршрута Google-ключи не требуются, а прямого обращения к Google при ошибке распознавания нет. Новая ветка не повторяет запрос автоматически. При неудаче пользователь получит обычное сообщение о невозможности расшифровки.

OGG/Opus из Telegram передаётся без перекодирования. Также предусмотрены форматы WAV, MP3, M4A, FLAC, AAC и WebM; фактическая поддержка конкретного файла зависит от провайдера модели. Ограничения этой ветки: файл до 20 MiB, запрос до 60 секунд, ответ до 8192 токенов. Обрезанный ответ не публикуется как полная расшифровка.

Короткое русское OGG/Opus-аудио проверено реальным запросом: точная расшифровка на этой модели, HTTP 200. Это проверка совместимости, а не гарантия точности на любом звуке. OpenRouter тарифицирует аудио по своему прайсу. Пересказ длинной расшифровки и последующая беседа используют прежнюю основную текстовую модель и оплачиваются отдельно.

## Молча игнорировать аудио

```env
VOICE_TRANSCRIPTION_PROVIDER=off
```

Бот пропускает входящие голосовые и audio-вложения: не скачивает файл, не запускает расшифровку, не показывает «печатает», не отправляет ошибку и не списывает ответ в платной личке. Проверка присутствия владельца в группе сохраняется, поэтому запрещённую группу бот всё равно покинет. Текстовые сообщения, текстовые реплаи на аудио и служебные события оплаты продолжают обрабатываться.

Удаление Google-ключей не заменяет этот режим.

## Установка обновления

1. Найдите каталог именно работающей копии бота: в нём должны быть `package.json`, `.env`, `src` и `data`.
2. Остановите текущий процесс. При ручном запуске в tmux или screen нажмите `Ctrl+C` в его окне. При использовании PM2 остановите только процесс этого бота.
3. Сохраните резервную копию текущего кода, рабочего `.env` и всей папки `data`.
4. Скопируйте содержимое папки `sych-bot` из архива в каталог установки. Рабочие `.env` и `data` сохраните. В архиве нет действующих ключей и пользовательских данных. `.env.example` служит только образцом, не подменяет ваш `.env`.
5. Выберите один режим в `.env`. Для сервера без прямого доступа к Google используйте `openrouter`; для полного отключения аудио используйте `off`.
6. Из каталога проекта выполните `npm ci --omit=dev`, затем запустите бот прежним способом. Для ручного запуска команда `npm start`. При PM2 используйте прежнее имя процесса и обновите его окружение, если переменные задавались через PM2.
7. В логах проверьте строку `[VOICE] provider=openrouter`, `[VOICE] provider=off` или `[VOICE] provider=google` и отсутствие ошибки запуска. В режиме OpenRouter отправьте короткое голосовое, в режиме off убедитесь, что оно осталось без реакции, затем проверьте ответ на текст.

При ошибке обновления остановите новый процесс и верните резервную копию кода с прежними настройками. Живую папку `data` сохраняйте, чтобы не потерять новые балансы и события оплаты.

## Если режим не применился

Убедитесь, что изменён `.env` работающей копии и процесс перезапущен. Переменные окружения процесса имеют приоритет над `.env`: если значение задано в PM2, systemd или оболочке, обновите его там же. Не запускайте второй экземпляр бота с тем же Telegram-токеном.

Опечатка в названии режима, отсутствие ключа для OpenRouter или другой `AI_BASE_URL` вызывают понятную ошибку при старте. Значения ключей в этих ошибках не печатаются. В логах распознавания OpenRouter выводятся только краткие причины, например `TIMEOUT`, `TRUNCATED` или `REQUEST_FAILED status=429`.

Этот переключатель относится только к голосовым сообщениям и audio-вложениям. Он не добавляет голос в платную личку, где пока разрешён только текст, и не добавляет транскрипцию в скрытые `/ask` и `/say`. Анализ видео, поиск через Google и другие нативные функции не переводятся в OpenRouter этим параметром.
